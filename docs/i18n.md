# Localization (i18n) API

**Doc type:** Java API · **Verified against 0.6.3**

The internationalization/localization system: how translations get onto the server, how keys are named, and how to read one back.

## Overview

Implemented in `com.hypixel.hytale.server.core.modules.i18n` (module) and `.i18n.event` (events). Translations reach the server one way — **`.lang` files** under `Server/Languages/<lang>/` of an asset pack: the base game's `Server/Languages/en-US/server.lang`, or your plugin's own asset pack (`src/main/resources/Server/Languages/en-US/<name>.lang`, with `"IncludesAssetPack": true`). On top of that the module provides:
- `GenerateDefaultLanguageEvent` — a **development-time** hook (dispatched by the `/lang gen` command, *not* at startup) through which plugins emit their default `.lang` files from a `TranslationMap` per namespace
- `I18nModule` — the server-side lookup (`getMessage`) and the `MessagesUpdated` live-reload event
- `MessageUtil` / `MessageFormat` — helpers that turn messages into plain text and localized lists

## Architecture
```
Asset pack (base game, or a plugin with "IncludesAssetPack": true)
└── Server/Languages/<lang>/<file>.lang        key = value   (# comments, "quoted", \ continuations)
      └── loaded by I18nModule as  <file>.<key>
            e.g. server.lang ──▶ "server.npcRoles.Bear_Grizzly.name"
                 my_plugin.lang ──▶ "my_plugin.greeting"

/lang gen   (dev-time; the base pack must be writable)
└── GenerateDefaultLanguageEvent
      └── putTranslationFile(namespace, TranslationMap)  ──▶  Server/Languages/en-US/<namespace>.lang
```

## Shipping translations with a plugin

Put a `.lang` file in your plugin's asset pack and the server loads it with everything else: `I18nModule` scans `Server/Languages/` of **every** registered asset pack (on `LoadAssetEvent` for packs present at boot, on `AssetPackRegisterEvent` for packs registered later). Each `<lang>/` directory is walked recursively for `*.lang`, and — for **mutable** packs only — the directory is handed to the asset monitor so edits reload live.

```
src/main/resources/
└── Server/
    └── Languages/
        └── en-US/
            └── my_plugin.lang
```

```
# my_plugin.lang — one `key = value` per line
greeting = Hello, world!
farewell = "Goodbye!"
homes.header = Your homes
```

**Every key is prefixed with the file name** (`I18nModule` builds the prefix from the path below `Languages/<lang>/`, `/` → `.`, `.lang` dropped), so the entries above are addressed as `my_plugin.greeting`, `my_plugin.farewell` and `my_plugin.homes.header` — from Java (`Message.translation("my_plugin.greeting")`), in `.ui` files (`%my_plugin.greeting`) and from `I18nModule.getMessage`. This is why the built-in `server.lang` yields keys such as `server.commands.…` and `server.npcRoles.<Role>.name`. Sub-folders add segments (`en-US/quests/main.lang` → `quests.main.<key>`).

Parser rules (`LangFileParser.parse(String source, BufferedReader)`):

- Blank lines and lines starting with `#` are skipped. Keys and values are trimmed around the **first** `=`.
- A **single-line** value wrapped in `"` has the quotes stripped. Quotes are *not* stripped from a continued value, so write `"…"` only on one-line entries.
- A trailing `\` continues the value on the next line; `\n` and `\t` escapes are expanded when the entry is stored.
- A malformed line (no `=`, empty key, empty value) is **skipped with a WARN** — `<file>:<line>: skipped malformed line (<reason>): <text>` — and the rest of the file still loads. (the nested `TranslationParseException` that 0.5.9's parser threw to fail the whole file was removed by 0.6.3; `parse` also gained the leading `source` argument used in those log lines.)
- A file ending mid-continuation logs `<file>:<line>: unterminated line continuation for key '<key>', keeping the text read so far` and still stores the partial value.
- A duplicate key **within one file** keeps the first definition and logs `<file>:<line>: duplicate translation key '<key>', keeping the first definition`.
- The same *prefixed* key defined by two files or packs also keeps the first, logging `'<key>' has multiple definitions: ...` (the message quotes both values) — but only when the two values actually differ; identical redefinitions are silent.

## GenerateDefaultLanguageEvent

**Package:** `com.hypixel.hytale.server.core.modules.i18n.event`

Implements `IEvent<Void>`. **Not a startup event**: it is dispatched by the `/lang gen` command (aliases `/i18n gen`, `/translation gen`, `/internationalization gen`; `--clean` drops on-disk keys that are no longer generated). Each `putTranslationFile(namespace, map)` becomes `Server/Languages/en-US/<namespace>.lang` in the **base** asset pack, merged with what is already on disk (existing values win). The command refuses when the base pack is immutable (a packaged install), so this is a tool for producing default files during development — runtime registration goes through `.lang` files as above.

| Method | Return Type | Description |
|--------|-------------|-------------|
| `putTranslationFile(String, TranslationMap)` | `void` | Contribute the entries that become `<namespace>.lang` |

`TranslationMap` (`server.core.modules.i18n.generator`): `put(String, String)`, `get(String)`, `size()`, `asMap()`, `removeKeys(Collection)`, `putAbsentKeys(TranslationMap)`, `sortByKeyBeforeFirstDot()`.

> **See also:** [Plugin Lifecycle](plugin-lifecycle.md#server-lifecycle-events)

## Usage Example

```java
import com.hypixel.hytale.server.core.modules.i18n.event.GenerateDefaultLanguageEvent;
import com.hypixel.hytale.server.core.modules.i18n.generator.TranslationMap;

@Override
protected void setup() {
    // Contribute defaults when a developer runs /lang gen. Keys are written
    // WITHOUT the namespace — the file name ("my_plugin.lang") supplies it on load.
    getEventRegistry().register(GenerateDefaultLanguageEvent.class, event -> {
        TranslationMap translations = new TranslationMap();
        translations.put("greeting", "Hello, world!");   // → my_plugin.greeting
        translations.put("farewell", "Goodbye!");        // → my_plugin.farewell

        event.putTranslationFile("my_plugin", translations);
    });
}
```

## Resolving a key to text (server-side)

`GenerateDefaultLanguageEvent` *registers* translations; `I18nModule` *reads* one back. You need this when something can only accept a plain `String`, not a `Message` — e.g. a [`CustomUIHud`](ui-api.md#customuihud) label, which disconnects the client if you hand it a `Message`. You also can't defer localization to the client there, so resolve the key server-side first.

**Package:** `com.hypixel.hytale.server.core.modules.i18n`

| Member | Return Type | Description |
|--------|-------------|-------------|
| `I18nModule.get()` | `I18nModule` | The module singleton |
| `getMessage(String language, String key)` | `String` | Translated text for `key` in `language`, falling back to the server's bundled defaults; `null` if unknown. `[TMP]` markers are stripped unless the server config enables `DisplayTmpTagsInStrings` |
| `getMessages(String language)` | `Map<String, String>` | All key→text pairs for a language (`null` language = `DEFAULT_LANGUAGE`) |
| `I18nModule.DEFAULT_LANGUAGE` | `static final String` | `"en-US"` — the language to pass when you have no per-client locale |

```java
import com.hypixel.hytale.server.core.modules.i18n.I18nModule;

// Resolve an entity's display-name key (a translation) to plain text.
// Note the "server." prefix: the key lives in server.lang.
String name = I18nModule.get()
    .getMessage(I18nModule.DEFAULT_LANGUAGE, "server.npcRoles.Bear_Grizzly.name"); // → "Grizzly Bear"
```

Lookup walks two fallbacks before giving up. First `getMessages(language)` merges the language's own entries over its **fallback language** — read from `Server/Languages/fallback.lang`, a flat `properties` file mapping a locale to the locale that backs it (`en-GB = en-US`, `es-MX = es-ES`, …), defaulting to `DEFAULT_LANGUAGE`. If the key is still missing, `getMessage` tries the **bundled defaults** loaded from `bundledDefaults/*.lang` on the server classpath. Only then does it return `null`.

Translation values for the built-in languages live in `Server/Languages/<lang>/server.lang` (e.g. `en-US`), so every built-in key starts with `server.`. NPC display-name keys look like `server.npcRoles.<Role>.name` (the NPC role JSON's `NameTranslationKey`); an entity's `DisplayNameComponent.getDisplayName()` is itself a translation `Message`, so read its [`getMessageId()`](player.md#getters) and pass that here.

## MessagesUpdated

**Package:** `com.hypixel.hytale.server.core.modules.i18n.event`

Implements `IEvent<Void>`. Fired by `I18nModule` when server translations **change at runtime** — language files reloaded from disk, or message assets edited live through the asset editor. Both maps are keyed by language, then by translation key:

| Method | Return Type | Description |
|--------|-------------|-------------|
| `getChangedMessages()` | `Map<String, Map<String, String>>` | `language → (key → new text)` for added/changed entries |
| `getRemovedMessages()` | `Map<String, Map<String, String>>` | `language → (key → old text)` for removed entries |

Listen for it if you cache resolved translation text (e.g. strings resolved via [`I18nModule.getMessage`](#resolving-a-key-to-text-server-side) and pushed into a HUD) and need to invalidate that cache:

```java
import com.hypixel.hytale.server.core.modules.i18n.event.MessagesUpdated;

getEventRegistry().registerGlobal(MessagesUpdated.class, event -> {
    if (event.getChangedMessages().containsKey("en-US")) {
        // re-resolve any cached en-US strings
    }
});
```

## MessageUtil — resolving and rendering messages

**Package:** `com.hypixel.hytale.server.core.util`

Static helpers around `Message` / `FormattedMessage`. The everyday one is `formatMessageToPlainString`, which turns the wire form of a message (`Message.getFormattedMessage()`, chat-event payloads, …) back into plain text — resolving its translation key via `en-US` and expanding `{param}` placeholders, ICU-style plural/select blocks, and nested children:

| Member | Return Type | Description |
|--------|-------------|-------------|
| `formatMessageToPlainString(FormattedMessage)` | `String` | Plain text of a formatted message (translation resolved in `en-US`; falls back to the raw key) |
| `formatText(String, Map<String, ParamValue>, Map<String, FormattedMessage>)` | `String` | Expand `{param}` / plural / select syntax in an already-resolved pattern |
| `toAnsiString(Message)` | `AttributedString` | Render a message (with its colors) for the server console (JLine) |
| `hexToStyle(String)` | `AttributedStyle` | Convert a `#RRGGBB` color to the nearest console style |
| `containsControlCharacters(String)` | `boolean` | True if the string holds ASCII/C1 control characters (input sanitizing) |

`sendSuccessReply` / `sendFailureReply` also live here but are **deprecated** asset-editor reply helpers — not for general plugin use.

```java
import com.hypixel.hytale.server.core.util.MessageUtil;

// e.g. log what a player actually saw
String plain = MessageUtil.formatMessageToPlainString(message.getFormattedMessage());
```

## MessageFormat — list formatting

**Package:** `com.hypixel.hytale.server.core.util.message`

One static helper for presenting a collection as a localized list `Message`:

```java
public final class MessageFormat {
    public static Message list(@Nullable Message header, Collection<Message> values);
}
```

Small collections (≤ 4 values) render inline separated by the `server.formatting.list.itemSeparator` translation; larger ones render one `server.formatting.list.row` per line. A non-null `header` is prefixed via `server.formatting.list.header` (with `header` and `count` params, plus `server.formatting.list.inlineHeaderSuffix` in the inline case), and an empty collection renders `server.formatting.list.empty`. (These are the `formatting.list.*` entries of `server.lang`.) Handy for command output:

```java
import com.hypixel.hytale.server.core.util.message.MessageFormat;

Message list = MessageFormat.list(
    Message.translation("my_plugin.homes.header"),
    homes.stream().map(Message::raw).toList());
playerRef.sendMessage(list);
```

## Notes

- Ship translations as `Server/Languages/<lang>/<name>.lang` files in your plugin's asset pack; `GenerateDefaultLanguageEvent` only helps you *generate* such files during development
- The file name is the namespace: `my_plugin.lang` → `my_plugin.<key>`, which keeps plugin keys from colliding with `server.*`
- Translations are used for player-facing messages (`Message.translation`) and UI elements (`%key` in `.ui` files)

## Gotchas & Errors

- **Symptom:** `<file>.lang:<n>: skipped malformed line (missing '=' | empty key | empty value): …` in the log → that line was dropped (as of 0.6.3 the rest of the file still loads). Fix: give the line a non-empty key and value; a value that must be empty can be written as `""`.
- **Symptom:** `'<key>' has multiple definitions: …` → two `.lang` files (or two packs) define the same *prefixed* key; the first one loaded wins. Fix: namespace by file name (`my_plugin.lang`) rather than reusing `server.lang` keys.
- **Symptom:** a `Message.translation("…")` (or `%key` in a `.ui` file) renders as the raw key on the client → no loaded translation has that exact key. Check the prefix first: the key includes the **file name** (`my_plugin.lang` → `my_plugin.greeting`), the file must sit under `Server/Languages/<lang>/` of an asset pack, and a plugin pack needs `"IncludesAssetPack": true` (see [Shipping translations with a plugin](#shipping-translations-with-a-plugin)).
- **Symptom:** `/lang gen` replies **"The assets folder is presently immutable and cannot be modified"** (`server.commands.i18n.gen.immutable`) and writes nothing → generation targets the *base* asset pack, which is read-only in a packaged install. It is a development-checkout tool; at runtime ship `.lang` files instead (see [GenerateDefaultLanguageEvent](#generatedefaultlanguageevent)).
- **Symptom:** "Attempted to add invalid default translation message" at startup → an asset-derived default (e.g. a crafting-bench category name that `I18nModule` turns into `server.items.<id>.bench.…` keys) had a null key or value; it is skipped. Fix the offending asset's `Name` field.
