# Asset Baseline

Snapshot of the Hytale game build that the `docs/` were fact-checked against.
When the docs make claims about asset structure or file formats (e.g.
`blockymodel-format.md`, `blockyanim-format.md`, `02-structure.md`), they were
verified against the build recorded here. Diff against this baseline after a
game update to see exactly which assets changed before re-checking docs.

> **Refreshed only after re-verification, not with the build.** This baseline is
> updated at the *end* of an update pass, once the pages referencing the drifted
> assets have been re-verified and stamped. The 0.6.3 pass shows why: refreshing
> the baseline early would have absorbed 4,329 changed lines into the "known good"
> state and destroyed the only signal saying which docs still needed looking at.
> (The 0.6.8 pass had just 4 translation files to absorb; the 0.7.2 pass absorbed
> about 13,900 added, modified or removed assets across both indexes.)

`CommonAssetsIndex.hashes` is Hytale's own per-asset SHA-256 index (paths are
relative to `Common/`), copied verbatim from the extracted assets. It is the
authoritative drift detector — one line per Common asset.

`ServerAssetsIndex.hashes` is **our own generated index** of the other half of
the archive — `Server/` and `Cosmetics/` (paths relative to the assets root,
`manifest.json` excluded). Hytale ships no hash index for these, yet they hold
the item/drop/prefab/worldgen/NPC JSON configs that a large share of the docs
document; before build-20 a Server-side change was invisible to the baseline
diff (build-16's "Server-side delta only" went unexamined for exactly this
reason). Regenerate with `maintenance/scripts/hash-server-assets.sh` — output
is path-sorted (`LC_ALL=C`), so plain `diff` against it is already a stable
content comparison.

## Detecting drift after a game update

`maintenance/scripts/update-build.sh` runs both drift checks (and everything
else mechanical) in one command — the manual forms below are what it does under
the hood.

Re-extract the current assets (see CLAUDE.md → "Inspecting assets on Linux"),
then diff the live indexes against this baseline:

```bash
diff maintenance/baseline/CommonAssetsIndex.hashes ~/.cache/hytale-assets/CommonAssetsIndex.hashes
maintenance/scripts/hash-server-assets.sh | diff maintenance/baseline/ServerAssetsIndex.hashes -
```

- No output → Common assets are byte-identical; format docs almost certainly still hold.
- Changed/added/removed lines → those exact assets changed. Re-verify any doc
  that references them (asset paths whose hash changed are the ones to re-check).

> **Caveat — reordering vs. content drift.** The index is not stably sorted, so a
> patch can re-shuffle its line order without changing any asset, producing a huge
> raw `diff` (the build-14 → build-15 bump was a 5.4 MB diff that turned out to be
> *zero* content changes). When the raw diff looks large, compare content only:
>
> ```bash
> diff <(LC_ALL=C sort maintenance/baseline/CommonAssetsIndex.hashes) \
>      <(LC_ALL=C sort ~/.cache/hytale-assets/CommonAssetsIndex.hashes)
> ```
>
> Empty output here = Common assets byte-identical despite the reordering (refresh
> the baseline file anyway so the cheap raw `diff` goes clean next time).

Also compare the build marker: if `install/.../sig/` now shows a build newer than `build-34`
(or `Implementation-Version` advances past `0.7.2`), the game updated. Update the
table above and refresh both snapshots once the docs have been re-verified
against the new build:

```bash
cp ~/.cache/hytale-assets/CommonAssetsIndex.hashes maintenance/baseline/
maintenance/scripts/hash-server-assets.sh > maintenance/baseline/ServerAssetsIndex.hashes
python3 maintenance/scripts/check-asset-ids.py --report-typing --dump-typing maintenance/baseline/AssetIdTyping.txt   # the asset-id gate's typing snapshot
```
